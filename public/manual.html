앱으로 돌아가기빠른 시작화면 구성발표 시연판정 기준표본 인쇄Raspberry Pi문제 해결

앱의 역할

카메라로 촬영한 원형 표본을 CLIP 이미지 벡터로 바꾸고, JSON DB에 등록된 정상·불량 설명 벡터와 비교합니다.

01대상 검출중앙 ROI와 영상 대비 확인
02벡터 생성CLIP image encoder
03설명 비교정상·불량 prompt 상대 점수
04판정·저장신호등 변경과 JSONL 기록

빠른 시작

카메라 없이 확인

  1. 실행 엔진을 리허설로 선택합니다.
  2. 하단 표본 8개 중 하나를 선택합니다.
  3. 현재 화면 판정을 누릅니다.
  4. 처리 단계, 점수 막대와 신호등을 확인합니다.

실제 CLIP 확인

  1. CLIP 모델 로드를 누릅니다.
  2. 최초 다운로드가 끝나 CLIP 준비됨이 표시될 때까지 기다립니다.
  3. 실행 엔진을 실제 CLIP으로 선택합니다.
  4. 표본 또는 카메라 화면을 판정합니다.
최초 CLIP 실행에는 약 150 MB 모델 다운로드가 필요합니다. 이후에는 브라우저 캐시를 사용합니다.

10분 발표에서 보여주는 순서

  1. 리허설 모드에서 정상 표본을 선택해 초록 신호등을 보여줍니다.
  2. 긁힘 표본을 선택해 점수 막대와 빨간 신호등, 저장 이력을 보여줍니다.
  3. 실제 CLIP으로 변경하고 같은 표본을 판정합니다.
  4. zero-shot CLIP이 불량 후보를 찾더라도 임계값 또는 종류 구분에서 흔들리는 장면을 설명합니다.
  5. 이 결과를 Siamese 학습의 필요성으로 연결합니다. 실제 정상·불량 쌍을 이용해 같은 종류를 가깝게 학습해야 한다는 결론입니다.
핵심 메시지: CLIP은 설명만으로 후보를 찾지만, 산업 현장의 경계는 실제 표본 쌍과 판정 목적이 다시 만들어야 합니다.

Raspberry Pi 5 실행

unzip clip-defect-demo-rpi5.zip -d clip-defect-demo
cd clip-defect-demo
./scripts/install-pi.sh
./scripts/start.sh

Pi에 연결된 Chromium에서 http://localhost:4173을 엽니다. 부팅 자동 실행은 ./scripts/install-service.sh을 사용합니다.

Hailo 장치 확인은 ./scripts/check-hailo.sh을 실행합니다. 현재 기본 CLIP 추론은 브라우저 ONNX/WASM이며, 실제 Hailo 가속에는 Hailo용 HEF와 inference worker 연결이 필요합니다.

문제 해결

카메라가 열리지 않음Pi의 Chromium에서 localhost로 접속하고 카메라 권한을 허용합니다. USB 카메라는 다른 앱이 사용 중인지 확인합니다.
표본이 너무 작음카메라를 가까이 옮기거나 매크로 렌즈를 사용해 검출 크기를 180 px 이상으로 맞춥니다.
CLIP 로드 실패첫 실행의 인터넷 연결을 확인하고 페이지를 새로고침한 후 모델을 다시 로드합니다.
불량이 정상으로 나옴임계값만 낮추기 전에 조명과 ROI를 확인합니다. 실제 CLIP의 한계일 수 있으므로 리허설 결과와 비교합니다.
Hailo 미감지hailortcli fw-control identify와 HailoRT 설치 상태를 확인합니다.
이 앱은 기술 시연용입니다. 실제 생산 판정에는 제품별 데이터셋, 오검출 평가, 장비 교정과 안전한 작업자 검토 절차가 필요합니다.
